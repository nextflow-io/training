## एक प्रशिक्षण वातावरण शुरू करो

GitHub Codespaces पर हमारे द्वारा प्रदान किए गए pre-built वातावरण का उपयोग करने के लिए, नीचे दिए गए "Open in GitHub Codespaces" बटन पर क्लिक करो। अन्य विकल्पों के लिए, [वातावरण के विकल्प](../envsetup/index.md) देखो।

हम सुझाव देते हैं कि प्रशिक्षण वातावरण को एक नए ब्राउज़र टैब या विंडो में खोलो (अपने उपकरण के अनुसार right-click, ctrl-click या cmd-click का उपयोग करो) ताकि वातावरण लोड होते समय तुम पढ़ते रह सको।
कोर्स के दौरान काम करने के लिए तुम्हें इन निर्देशों को साथ-साथ खुला रखना होगा।

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/nextflow-io/training?quickstart=1&ref=master)

### वातावरण की मूल बातें

इस प्रशिक्षण वातावरण में प्रशिक्षण कोर्स के लिए आवश्यक सभी सॉफ़्टवेयर, कोड और डेटा मौजूद हैं, इसलिए तुम्हें खुद कुछ भी इंस्टॉल करने की ज़रूरत नहीं है।

codespace एक VSCode इंटरफ़ेस के साथ सेट किया गया है, जिसमें एक filesystem explorer, एक code editor और एक terminal shell शामिल है।
कोर्स के दौरान दिए गए सभी निर्देश (जैसे 'फ़ाइल खोलो', 'कोड संपादित करो' या 'यह कमांड चलाओ') जब तक अन्यथा न कहा जाए, VSCode इंटरफ़ेस के इन्हीं तीन हिस्सों को संदर्भित करते हैं।

अगर तुम यह कोर्स अकेले कर रहे हो, तो कृपया अधिक जानकारी के लिए [वातावरण की मूल बातें](../envsetup/01_setup.md) से परिचित हो जाओ।

### संस्करण आवश्यकताएँ

यह प्रशिक्षण Nextflow 25.10.2 या बाद के संस्करण के साथ **v2 syntax parser** के साथ काम करता है, जो Nextflow 26.04 से डिफ़ॉल्ट है।
हमारे प्रशिक्षण वातावरण में तुम्हें कुछ भी करने की ज़रूरत नहीं है: यह v2 parser के साथ Nextflow 26.04.4 चलाता है। अगर तुम एक लोकल या कस्टम वातावरण का उपयोग कर रहे हो, तो [संस्करण नोट्स](../info/nxf_versions.md) देखो।

!!! warning "nf-core/demo के लिए Nextflow 25.10.4 या बाद का संस्करण आवश्यक है"

    Part 1 में उपयोग की जाने वाली `nf-core/demo` पाइपलाइन अपना न्यूनतम Nextflow संस्करण (`>=25.10.4`) लागू करती है, जो 25.10.2 की सामान्य प्रशिक्षण सीमा से अधिक सख्त है।
    हमारा प्रशिक्षण वातावरण पहले से ही इसे पूरा करता है; अगर तुम एक लोकल या कस्टम वातावरण का उपयोग कर रहे हो, तो सुनिश्चित करो कि तुम Nextflow 25.10.4 या बाद के संस्करण पर हो।

इस प्रशिक्षण के लिए अतिरिक्त रूप से **nf-core tools 4.0.2** की आवश्यकता है।
अगर तुम nf-core tooling का कोई अलग संस्करण उपयोग करते हो, तो तुम्हें साथ चलने में कठिनाई हो सकती है।

तुम `nf-core --version` कमांड का उपयोग करके जाँच सकते हो कि तुम्हारे वातावरण में कौन सा संस्करण इंस्टॉल है।

!!! warning "v2 parser संगतता"

    कई nf-core पाइपलाइनें अभी तक v2 syntax parser को सपोर्ट नहीं करती हैं।
    अगर तुम इस कोर्स में उपयोग की गई पाइपलाइनों के अलावा कोई nf-core पाइपलाइन चलाते हो और त्रुटियाँ आती हैं, तो तुम्हें `export NXF_SYNTAX_PARSER=v1` सेट करके v1 parser पर स्विच करना पड़ सकता है।
    विवरण के लिए [संस्करण नोट्स](../info/nxf_versions.md) देखो।

## काम के लिए तैयार हो जाओ

एक बार जब तुम्हारा codespace चल रहा हो, तो प्रशिक्षण में उतरने से पहले तुम्हें दो काम करने होंगे: इस विशिष्ट कोर्स के लिए अपनी working directory सेट करो, और प्रदान की गई सामग्री पर एक नज़र डालो।

### Working directory सेट करो

डिफ़ॉल्ट रूप से, codespace सभी प्रशिक्षण कोर्सों की root पर work directory सेट करके खुलता है, लेकिन इस कोर्स के लिए हम `nfcore-use/` डायरेक्टरी में काम करेंगे।

terminal में यह कमांड चलाकर अभी directory बदलो:

```bash
cd nfcore-use/
```

!!! tip "सुझाव"

    अगर किसी भी कारण से तुम इस डायरेक्टरी से बाहर चले जाते हो (जैसे तुम्हारा codespace सो जाए), तो तुम हमेशा इसमें वापस आने के लिए पूरे path का उपयोग कर सकते हो, यह मानते हुए कि तुम इसे Github Codespaces प्रशिक्षण वातावरण के भीतर चला रहे हो:

    ```bash
    cd /workspaces/training/nfcore-use
    ```

अब, इस डायरेक्टरी की सामग्री देखो।

### प्रदान की गई सामग्री देखो

तुम training workspace के बाईं ओर file explorer का उपयोग करके इस डायरेक्टरी की सामग्री देख सकते हो।
वैकल्पिक रूप से, तुम `tree` कमांड का उपयोग कर सकते हो।

```bash
tree .
```

??? abstract "डायरेक्टरी सामग्री"

    ```console
    .
    ├── custom.config
    ├── laptop.config
    ├── malformed_samplesheet.csv
    └── my_params.yml
    ```

- **`laptop.config` फ़ाइल** एक configuration फ़ाइल है जिसे हम section 4 में लोकल स्तर पर production-scale पाइपलाइन चलाते समय resource उपयोग को सीमित करने के लिए उपयोग करेंगे।
  तब तक तुम इसे नज़रअंदाज़ कर सकते हो।
- **`my_params.yml`, `malformed_samplesheet.csv`, और `custom.config` फ़ाइलें** Part 2 में उपयोग की जाती हैं, जो किसी फ़ाइल से पैरामीटर सेट करना, इनपुट validation, और process-level configuration overrides दिखाने के लिए हैं।
  तब तक तुम इन्हें भी नज़रअंदाज़ कर सकते हो।
